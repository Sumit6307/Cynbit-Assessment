1.2 API Structure & Payload Analysis

Cynbit avoids classic RESTful JSON endpoints (/api/*) in favor of Next.js React Server Actions. These actions run server-side over HTTP POST and are bound to compiled hashes:

1. Contact Inquiry Action (submitInquiry) ID: 40247ba4465344b3386595bab4303317cdcce907df

Route: POST /contact | Encoding: multipart/form-data

  • Fields: fullName (text), email (email), company (optional), industry (optional), message (text).
  • Response Contract: Returns JSON { "success": true } or { "success": false, "error": "Something went wrong..." }.
2. Candidate Application Action (submitCandidateApplication) ID: 40645a00e04f6854903cf3a65fda4c75ddd7691de9

Route: POST /careers/[slug] | Encoding: multipart/form-data

  • Flat Metadata: jobId, fullName, email, phone, linkedinUrl, professionalProfileUrl, message, agreedToTerms.
  • Complex Serialized Payload: educationData is transmitted as a serialized JSON string array (JSON.stringify(array)) containing qualification level, degree, university, graduation year, and score.
  • Binary Attachment: resume transmitted as a multipart file stream.
  • Response Contract: { success: boolean, isDuplicate?: boolean, trackingUrl?: string, error?: string }. Synchronous execution includes database persistence and unique record validation.
3. Administrative Portal Login (loginToPortal) ID: 40d93da1cc26de4ef37bcb273184b7141ef77a50f8

Route: POST /portal | Payload: password (Security Key string)

  • Client sets localStorage.setItem("cynbit_portal_last_activity", Date.now().toString()) and redirects to /dashboard.
  • Unauthenticated requests to /dashboard are deflected via 307 Temporary Redirect back to root.

2.2 Detailed Analytical Findings

1. Authentication Architecture Weaknesses on Internal Portal

The internal administrative gateway at portal.cynbit.in authenticates administrators using a single input labeled "Security Key" that submits a single password parameter. This architecture exhibits three key limitations:

  • Lack of Individual Accountability: Shared secrets cannot distinguish between team members or contractors. An action taken cannot be attributed to a specific person.
  • Key Rotation Overhead: When any team member departs, the master key must be updated and manually distributed to all staff.
  • Tamperable Inactivity Tracking: Storing session expiration timestamps in browser localStorage (cynbit_portal_last_activity) is client-controlled and vulnerable to manipulation or XSS exfiltration.
2. Incomplete DNS Email Authentication (SPF / DMARC)

Passive DNS inspection indicates:

  • SPF Record: v=spf1 include:secureserver.net -all
  • MX Record: cynbit-in.mail.protection.outlook.com (Microsoft 365)
  • DMARC Record: v=DMARC1; p=none;

Impact: Because the SPF record only lists GoDaddy (secureserver.net) and omits Microsoft 365, emails sent from Cynbit's corporate mailbox to candidates or clients will fail SPF checks on strict receiving mail servers (Google Workspace, Yahoo, corporate gateways). With DMARC set to p=none, domain spoofing goes unquarantined.

3. Data Validation & File Handling Risks
  • Unvalidated Stringified JSON: educationData is passed as a stringified JSON array inside FormData. If the backend invokes JSON.parse() without deep schema validation (e.g. Zod), unexpected keys, extreme lengths, or non-array inputs can trigger uncaught edge exceptions.
  • Resume Ingestion: Resumes submitted via submitCandidateApplication require backend magic-byte verification (checking %PDF signatures) rather than trusting client-declared MIME types.
4. Serverless Performance & Synchronous Pipeline Bottlenecks

Executing candidate registration, duplicate database lookups, and SMTP email notifications synchronously inside a single Server Action increases edge execution time and risks hitting Vercel's execution timeouts under load. The pipeline should be decoupled using an asynchronous event queue.

const nextConfig = {

3.2 Robust Zod Validation & Type-Safe Server Action

Refactored submitCandidateApplication incorporating rate-limiting, deep JSON schema validation, and PDF magic-byte verification:

// app/actions/candidate.ts
'use server';

import { z } from 'zod';
import { rateLimiter } from '@/lib/rate-limiter';
import { enqueueApplication } from '@/lib/queue';
import { headers } from 'next/headers';

const EducationSchema = z.object({
  id: z.string(),
  qualificationLevel: z.string().min(1),
  degree: z.string().min(1),
  university: z.string().min(2),
  graduationYear: z.string().regex(/^\d{4}$/),
  status: z.enum(['Completed', 'Currently Pursuing', 'Expected to Graduate']),
});

const CandidateSchema = z.object({
  jobId: z.string().min(1),
  fullName: z.string().trim().min(2).max(100),
  email: z.string().trim().email().toLowerCase(),
  phone: z.string().regex(/^\+?[1-9]\d{7,14}$/, 'Invalid phone format'),
  linkedinUrl: z.string().url().regex(/linkedin\.com/),
  message: z.string().min(10).max(3000),
  agreedToTerms: z.literal(true),
  educationData: z.string().transform((str, ctx) => {
    try {
      return z.array(EducationSchema).min(1).parse(JSON.parse(str));
    } catch {
      ctx.addIssue({ code: z.ZodIssueCode.custom, message: 'Malformed education data structure' });
      return z.NEVER;
    }
  }),
});

export async function submitCandidateApplication(formData: FormData) {
  try {
    // 1. Sliding Window IP Rate Limiting
    const headerList = await headers();
    const ip = headerList.get('x-forwarded-for')?.split(',')[0].trim() || '127.0.0.1';
    const { success: allowed } = await rateLimiter.limit(`apply:${ip}`);
    if (!allowed) return { success: false, error: 'Rate limit exceeded. Please wait.' };

    // 2. Deep Schema Parsing
    const data = CandidateSchema.parse({
      jobId: formData.get('jobId'),
      fullName: formData.get('fullName'),
      email: formData.get('email'),
      phone: formData.get('phone'),
      linkedinUrl: formData.get('linkedinUrl'),
      message: formData.get('message'),
      agreedToTerms: formData.get('agreedToTerms') === 'on',
      educationData: formData.get('educationData'),
    });

    // 3. Magic-byte verification for PDF (%PDF -> 0x25 0x50 0x44 0x46)
    const file = formData.get('resume') as File;
    if (!file || file.size === 0) return { success: false, error: 'Resume is required' };
    if (file.size > 5 * 1024 * 1024) return { success: false, error: 'File exceeds 5MB limit' };

    const buffer = Buffer.from(await file.arrayBuffer());
    const isPdf = buffer[0] === 0x25 && buffer[1] === 0x50 && buffer[2] === 0x44 && buffer[3] === 0x46;
    if (!isPdf) return { success: false, error: 'Only genuine PDF documents permitted' };

    // 4. Instant Enqueueing (Guarantees < 200ms user latency)
    const submissionId = crypto.randomUUID();
    await enqueueApplication({ submissionId, data, buffer, fileName: file.name });

    return { success: true, trackingUrl: `/portal/track/${submissionId}` };
  } catch (err) {
    if (err instanceof z.ZodError) return { success: false, error: err.issues.map(i => i.message).join('. ') };
    return { success: false, error: 'Server error. Please reach out via email.' };
  }
}

3.3 Asynchronous Queue Pattern & Decoupled Processing

Decouple email notifications and cloud bucket storage from the immediate HTTP request cycle using an edge queue (e.g., Upstash QStash or Redis Queue):

// lib/queue.ts
import { Client } from '@upstash/qstash';

const qstash = new Client({ token: process.env.QSTASH_TOKEN! });

export async function enqueueApplication(payload: {
  submissionId: string;
  data: any;
  buffer: Buffer;
  fileName: string;
}) {
  await qstash.publishJSON({
    url: `${process.env.INTERNAL_WORKER_URL}/api/webhooks/process-application`,
    body: {
      submissionId: payload.submissionId,
      candidate: payload.data,
      resumeBase64: payload.buffer.toString('base64'),
      fileName: payload.fileName,
      timestamp: new Date().toISOString(),
    },
    retries: 3, // Automatic exponential backoff
  });
}

3.4 HttpOnly Cookie Session Middleware for Administrative Portal

Replace the single static security key on portal.cynbit.in with encrypted, tamper-resistant HTTP-only cookies and edge middleware route protection:

// middleware.ts (Protects /dashboard and /portal/admin)
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';
import { getIronSession } from 'iron-session';
import { sessionOptions, SessionData } from '@/lib/auth/session';

export async function middleware(request: NextRequest) {
  const res = NextResponse.next();
  const session = await getIronSession<SessionData>(request.cookies, res.cookies, sessionOptions);

  if (request.nextUrl.pathname.startsWith('/dashboard')) {
    if (!session.isLoggedIn || Date.now() > session.expiresAt) {
      session.destroy();
      const loginUrl = new URL('/portal', request.url);
      loginUrl.searchParams.set('redirect', request.nextUrl.pathname);
      return NextResponse.redirect(loginUrl);
    }
  }
  return res;
}

export const config = { matcher: ['/dashboard/:path*'] };
